# Publish ESP Flasher on Google Play

Application id: `dev.espflasher.app`  
CI uploads a **signed AAB** to the **internal** track as a **draft** by default.

Store listing files live in [`fastlane/metadata/android/`](fastlane/metadata/android/).
Launcher and Play graphics are generated by [`scripts/generate_icons.py`](scripts/generate_icons.py)
and [`store/capture-assets.mjs`](store/capture-assets.mjs).

## 1. Play Console app

1. Open [Google Play Console](https://play.google.com/console) (developer account required).
2. **Create app**
   - Name: `ESP Flasher`
   - Default language: English (United States)
   - App or game: **App**
   - Free
3. Finish the declarations that have no API (see [docs/data-safety.md](docs/data-safety.md) and the checklist below).
4. Confirm the package name you will upload is **`dev.espflasher.app`**.

## 2. Play App Signing + upload key

Play keeps the **app signing key**. CI only holds an **upload key**.

On a trusted machine (not this repo):

```bash
./scripts/create-upload-keystore.sh ./upload-keystore.jks espflasher
```

Save the `.jks` in a password manager. The script prints the four GitHub secrets.

First-time Console setup:

1. **Release → Setup → App signing**
2. Let Google generate the app signing key (default).
3. You will enroll the upload key on the **first AAB** CI uploads (or upload one AAB by hand).

## 3. Service account for CI

1. In Google Cloud, create (or reuse) a project.
2. Enable **Google Play Android Developer API**.
3. Create a **service account** (no roles required in Cloud).
4. Create a JSON key. Keep it off git.
5. Play Console → **Users and permissions** → Invite the service account email.
   Grant:
   - **View app information**
   - **Manage store presence** (for listing graphics)
   - **Release to testing tracks** (internal / closed / open)
   - **Release apps to production** (only if you want the production track from CI)
6. Wait until the invite shows as active (often a few hours the first time).

## 4. GitHub secrets and environment

Repo: [janisxyz/esp-flasher](https://github.com/janisxyz/esp-flasher)

1. **Settings → Environments → New environment** named `play`.
2. **Settings → Secrets and variables → Actions** (repo or the `play` environment):

| Secret | Contents |
| --- | --- |
| `PLAY_SERVICE_ACCOUNT_JSON` | Full JSON key file |
| `ESPFLASHER_KEYSTORE_BASE64` | `base64 -w0 upload-keystore.jks` |
| `ESPFLASHER_STORE_PASSWORD` | Keystore password |
| `ESPFLASHER_KEY_ALIAS` | `espflasher` (unless you changed it) |
| `ESPFLASHER_KEY_PASSWORD` | Key password (usually same as store) |

Optional: add a required reviewer on the `play` environment before production uploads.

## 5. GitHub Pages (privacy policy)

Play requires a public privacy-policy URL.

1. **Settings → Pages → Source: GitHub Actions**
2. Run the **GitHub Pages** workflow, or push to `main`.
3. Policy URL to paste in Play Console:

`https://janisxyz.github.io/esp-flasher/privacy.html`

## 6. Ship a build

**Preferred:** tag a release.

```bash
git tag v1.0.0
git push origin v1.0.0
```

That runs **Publish to Google Play**:

- `versionName` = tag without `v`
- `versionCode` = GitHub `run_number` (always increases)
- signed AAB
- upload to Play **internal** track, status **draft**
- GitHub Release with the AAB attached

**Manual:** Actions → **Publish to Google Play** → Run workflow. You can pick
`internal` / `alpha` / `beta` / `production` and `draft` / `completed`.

Keep the first uploads as **draft** until the store listing, content rating,
target audience, and data safety forms are complete. Play rejects `completed`
releases on an unfinished draft app.

## 7. Push listing graphics

After the first AAB exists in Console:

Actions → **Play Store listing** → Run workflow

or push changes under `fastlane/metadata/`.

This uploads:

- 512×512 high-res icon
- 1024×500 feature graphic
- 6 phone screenshots (1080×1920)
- 2 seven-inch and 2 ten-inch tablet screenshots
- EN + DE title, short/full description, changelog

## 8. Console checklist (manual)

These have no reliable CI API. Fill them once:

- [ ] Privacy policy URL
- [ ] App category: **Tools**
- [ ] Contact email
- [ ] Data safety — see [docs/data-safety.md](docs/data-safety.md)
- [ ] Content rating questionnaire (developer tool, no UGC, no violence)
- [ ] Target audience: **13 and up**, not designed for children
- [ ] News app: **No**
- [ ] COVID-19: **No**
- [ ] Ads: **No**
- [ ] Financial features: **No**
- [ ] Health: **No**
- [ ] Government / political: **No**
- [ ] Play App Signing enrolled
- [ ] Internal testing testers (your Gmail) if you want to install before production

USB host is declared `android:required="true"`, so Play only shows the app on
devices that report USB host.

## 9. Promote to production

1. Install the internal draft on a USB-OTG phone and flash a real board.
2. In Play Console, promote internal → closed/open testing if you want a wider ring.
3. Re-run **Publish to Google Play** with track `production` and status `completed`,
   or promote in the Console UI.
4. Production reviews typically take a few days on the first submit.

## Regenerating graphics

```bash
python3 scripts/generate_icons.py
node store/capture-assets.mjs   # needs Playwright (repo does not bundle it)
```

Do not put rounded corners on `icon.png`. Play applies the mask.
